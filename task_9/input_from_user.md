Rewrote the seed prompt in a natural colleague voice with a stated deadline, audience and reason for the build. The previous version opened with three consecutive "Use X as Y" sentences and carried evaluator phrasing ("the interaction must update", "the archive must include"), which reads as a rubric disguised as a prompt.

Promoted scene_reference.png from a loose visual reference to the layout specification. The prompt now requires the build to reproduce what the reference shows: the framed play area and its internal grid lines, the number of tokens and their row-by-row arrangement, the horizontal offset between rows, the collection strip and the placement of its label, the title, and the HUD column with its exact wording and line breaks. None of those values are stated in the prompt, so they have to be derived from the supplied image rather than read off the instructions. The previous version asked only for "multiple visible tokens arranged clearly", which any approximate layout satisfied.

Added two runtime telemetry formats, MOTION_SAMPLE once per second and ACTION_TRANSITION on every blast with an AUTO or INPUT origin, so the automatic preview cycle and the player trigger are separable in the output instead of being claims about transient screen state.

Replaced the single project-archive deliverable with three named outputs: Bomb_Chain_Reaction_Godot_Project.zip, bomb_blast_frame.png captured while the blast ring is still expanding with the HUD counters legible, and bomb_runtime_log.txt covering at least twelve continuous seconds and containing both an automatic and a player-triggered action line. The earlier single ZIP made the blast, the counters and the preview cycle impossible to verify from saved files, since none of that behaviour survives outside a running session.

Kept Bomb.glb as a live 3D element but tightened the requirement: it must render as an actual 3D object during play in its own viewport panel beside the board, with a dedicated camera and at least two lights placed so the silhouette and top surface both read against the dark background, and without overlapping the framed play area.

Rationale for the set of changes: the previous version was reported as solvable near-perfectly by three models. The difficulty now comes from deriving the layout from a supplied image, matching two exact telemetry formats, and producing artefacts that only exist if the project is actually built and run.
