# The task response format

Where every piece of a CUA v3 submission lives, and what a hand-built
`response.json` must contain. This is the input contract for
`audit_prepare.py`: everything `bundle.json` carries is derived from the files
described here.

**Nothing in this bundle fetches.** The task files are supplied on disk and
every script works offline.

**Project:** `6a0f76eb0ee35ab09571df8f` — "CUA Environment v3", 1,535 tasks.
Contributor-facing name: **Orangutan Encyclopedia**.

A worker writes a GUI-heavy prompt over ≥3 input files, builds ground-truth
files inside an Ubuntu VM, writes a weighted rubric, wires an
`agent_judge_multi` verifier, and runs an agent against it.

Workspace root: the directory containing this bundle. Override with
`CUA_AUDIT_HOME` if the data lives elsewhere.

## Where the files go

```
<workspace>/
├── tasks/<task_id>/
│   ├── response.json        REQUIRED — the task response (see below)
│   └── task_meta.json       the task record: domain, sub_domain, OS flags
├── attempts/<attempt_id>/   only when auditing one specific attempt
│   ├── response.json        REQUIRED
│   ├── attempt_meta.json    attempt role, reviewer verdict, timings
│   └── task_meta.json       the parent task record
└── audit/<unit_id>/         generated by audit_prepare.py
```

A **unit** is whichever of the two directories holds the `response.json`;
`audit_common.unit_dir()` checks `tasks/` first, then `attempts/`.

### `task_meta.json`

Keys are upper-case, as stored on the task record. Only `metadata` is read:

```json
{
  "TASK_ID": "6a62dc372071f153f642fc23",
  "STATUS": "pending",
  "BATCH": null,
  "metadata": {
    "domain": "Software & Data",
    "sub_domain": "Data Scientists & ML Engineers",
    "WORKER_SKILL_NAME": "Data Science",
    "ubuntu": "true"
  }
}
```

`domain` matters: it selects the weight-share bands for component 23. Only
`Design & Creative` inverts them; everything else uses the default bands.

### `attempt_meta.json`

```json
{
  "ATTEMPT_ID": "…", "TASK": "…", "ATTEMPTED_BY": "…", "ATTEMPTED_AT": "…",
  "ATTEMPT_VERSION": 2, "IS_REVIEW_FIX": "false", "IS_SEND_BACK_TO_QUEUE": "false",
  "REVIEW_STATUS": "…", "REVIEW_COMMENTS": "…", "REVIEWED_AT": "…",
  "TIME_SPENT_SECS": 4200
}
```

## Reading `response.json`

`response` is `{before: {step_id: step}, turns: [], after: {}, metrics: {},
dataSourceResults: {}}`. **`turns` is always empty** — everything is in
`before`. Step IDs carry random suffixes, so **select by `type`, never by id**.

```python
import json
b = json.load(open("response.json", encoding="utf-8"))["before"]

def step(t):  return next(s for s in b.values() if s.get("type") == t)
def steps(t): return [s for s in b.values() if s.get("type") == t]

def field(name):        # TextCollection appears 6-8x with different output keys
    return next(s["output"][name] for s in b.values()
                if s.get("type") == "TextCollection" and name in (s.get("output") or {}))
```

`audit_common.py` exposes these as `load()`, `step()`, `steps()` and `field()`.

### Prompt, rubric, verifier

| You want… | Path |
|---|---|
| Prompt as shipped | `step("PromptInput").output.content` |
| Rubric (authoritative, has MUST-PASS) | `step("RubricCriteriaBuilder").output.criteria` |
| Same rubric as sent to the VM | `step("ComputerUse").output.inputRubricCriteria` |
| Same rubric as sent to the verifier | `step("ComputerUse").output.verifierInput.evaluator.rubric.criteria` |
| Rubric the generator produced, pre-edit | the `ExternalApp` whose `output.items[0].content.data` has `criteria` |
| Verifier definition | `step("ComputerUse").output.verifierInput.evaluator` → `{func, expected[], result[], rubric}` |
| Verifier self-check result | `step("ComputerUse").output.verifierOutput` → `{evaluationScore, message}` |
| App family | `step("ComputerUse").output.taskProjectName` (e.g. `"office"`) |

Each criterion is
`{id, title, weight, annotations: {criteria_category, criteria_type}}` with
`criteria_category` in `format_gate` / `correctness` / `visual` and
`criteria_type` in `MUST-PASS` / `REGULAR`. `audit_prepare.py` writes this
list back out verbatim as `audit/<unit_id>/rubric.json`.

### Contributor form fields

All via `field(name)`:

| Field | Meaning |
|---|---|
| `prompt_changed`, `prompt_changes_made` | did they edit the seed prompt, and why |
| `init_file_upload[]` | uploaded **input** files |
| `asset_upload[]` | uploaded **ground-truth** files |
| `applications_used` | self-reported VM apps |
| `notes_for_reviewer`, `quality_confirmation` | handoff notes |
| `agent_works`, `agent_issue_details` | agent-run failure report |
| `sbq_needed` | `no_full_review` = proceeded, `yes_skip` = sent back |
| `trajectory_files` | intermediate files used to build the ground truth |

### Reviewer verdict

`step("QualityMeasurement").output.content`:

| Key | Meaning |
|---|---|
| `quality_task_overall` | the reviewer's **1–5 score** |
| `quality_instruction_following` | `yes` / `no` |
| `feedback_overall` | written feedback to the contributor |

This verdict describes the **previous** attempt on the task, not the
submission under review. It must never be used as a calibration target.

## Uploads and files

Every upload object carries both URL forms plus type metadata:

```json
{
  "name": "chemical_formula.png",
  "cdsUrl": "scale-cds://65cbc42b32ffab95dd54b864/wxpPfLtAgvo6mlv#s3/scale-cds-public-us-west-2",
  "s3Url":  "https://scale-cds-public-us-west-2.s3.amazonaws.com/65cbc42b32ffab95dd54b864/wxpPfLtAgvo6mlv",
  "url":    "scale-cds://…",              // same as cdsUrl
  "mimeType": "image/png",
  "fileType": "FILE_TYPE_IMAGE",          // or FILE_TYPE_DOCUMENT
  "fileSizeInBytes": 11730,
  "exifData": { … }                        // images only
}
```

Four places name the same files. Cross-check them — they can disagree:

| Purpose | Path |
|---|---|
| Inputs, as uploaded | `field("init_file_upload")[]` |
| Inputs, as placed in the VM | `step("ComputerUse").output.taskInitializerInput.config[].parameters.files[]` → `{path, url}` |
| Ground truth, as uploaded | `field("asset_upload")[]` |
| Ground truth, as graded | `…verifierInput.evaluator.expected[]` → `{dest, path, type: "cloud_file"}` |
| Agent outputs the verifier looks for | `…verifierInput.evaluator.result[]` → `{dest, path: "/home/docker/Desktop/…", type: "vm_file"}` |

### Resolving `scale-cds://` and staging the binaries

`scale-cds://<acct>/<key>#s3/<bucket>` → `https://<bucket>.s3.amazonaws.com/<acct>/<key>`

```python
import re
def cds_to_https(u):
    m = re.match(r"scale-cds://([^/]+)/([^#]+)#s3/(.+)", u)
    return f"https://{m.group(3)}.s3.amazonaws.com/{m.group(1)}/{m.group(2)}" if m else u
```

The `scale-cds-public-*` buckets are public — plain HTTPS fetches input and
ground-truth files with no credentials, which is what `audit_prepare.py` does.
The initializer's `type: "download"` config block is just this list of
`{path, url}` pairs, so it doubles as the manifest of what the agent starts
with.

**When the links have expired**, place the binaries yourself instead:
`audit/<unit_id>/files/inputs/<basename of the VM path>` and
`audit/<unit_id>/files/expected/<the verifier's dest string>`. Any file already
present and non-empty is reported `cached` and never re-fetched.

## Building a `response.json` by hand

Sometimes the submission arrives as loose files — a prompt, a rubric, an
inputs folder and a gold folder — rather than as a task response. The scripts
read only `response.json`, so assemble one. Four `before` nodes are enough for
a full review:

```json
{
  "before": {
    "step_prompt": {
      "type": "PromptInput",
      "output": { "content": "<the prompt text>" }
    },
    "step_rubric": {
      "type": "RubricCriteriaBuilder",
      "output": { "criteria": [ /* {id, title, weight, annotations} */ ] }
    },
    "step_cu": {
      "type": "ComputerUse",
      "output": {
        "taskInitializerInput": {
          "config": [{ "parameters": { "files": [
            { "path": "/home/docker/Desktop/input.csv", "url": "https://…" }
          ]}}]
        },
        "verifierInput": { "evaluator": {
          "func": "agent_judge_multi",
          "expected": [{ "dest": "report.xlsx", "path": "https://…" }],
          "result":   [{ "dest": "report.xlsx", "path": "/home/docker/Desktop/report.xlsx" }]
        }},
        "verifierOutput": { "evaluationScore": "1" }
      }
    },
    "step_text": {
      "type": "TextCollection",
      "output": { "prompt_changed": "true" }
    }
  }
}
```

Three things the mechanical pre-pass in `audit_common.py` will punish if you
get them wrong:

- **Omit `result` and component 28 fails automatically.** It compares the
  `dest` set of `expected` against that of `result`; an empty `result` reads as
  a total mismatch. Mirror `expected`, with `path` under
  `/home/docker/Desktop/`.
- **Omit the `url` / `path` strings and component 10 fails automatically.** It
  checks whether a ground-truth URL points at an input URL; if both sides are
  absent they compare equal. Give every file a distinct string even when it is
  a placeholder.
- **`func` must be `agent_judge_multi`**, or component 28 fails on the first
  clause.

`ExternalApp` (agent runs) and `QualityMeasurement` (the previous reviewer's
verdict) can be omitted entirely — nothing scores them.

## Agent runs, artifacts, trajectories

Optional, and absent from hand-built responses. The `ExternalApp` whose
`output.items[0].content.data` has `instances`:

```
data: { status, task_id, version, instances[] }
  instance: { instance_id, status, duration_seconds, task_version,
              created_at_utc, completed_at_utc, context }
    context:
      deployed_agents[] / deployed_envs[] / deployed_sandboxes[]
      prompt_responses[]                # what was asked and answered
      metadata:
        artifacts{}                     # path -> s3:// URI (final desktop state)
        collected_artifacts{}           # same, nested under "collect-artifacts"
        file_artifact_universe{id,version}
        verifications{<id>}             # the grading
        run_group_id, workflow_id, instance_id, task_id, a2a_conversations
```

Up to 6 instances are requested; fewer completing is normal. Filter on
`status == "completed"` before averaging anything. With no `ExternalApp` step,
`bundle.json` carries `agent_runs: {"present": false}`.

### `prompt_responses[]` — what the agent was actually asked

| Key | Meaning |
|---|---|
| `prompt_text` | **the prompt as run** — may differ from `PromptInput.output.content` |
| `response` | the agent's final text reply |
| `model`, `prompt_id` | e.g. `claude-opus-4-7`, `mm-cua-prompt` |
| `agent_trajectory_s3_uri` | full trajectory JSON for this run |
| `agent_session_id`, `a2a_context_id` | correlate with `metadata.a2a_conversations` |

Runs happen mid-authoring, so `prompt_text` is a snapshot. Of two tasks
sampled, one matched the shipped prompt exactly and one did not (960 vs 1583
chars). Compare them before treating a run as a test of the shipped task.

### Artifacts

`context.metadata.artifacts` maps VM path → `s3://frontier-data-environments/
artifacts/collected_artifacts/<instance_id>/<ts>/<path>`. It is the agent's
**final desktop state**, so it includes the input files alongside anything
produced. Keys encode dots as `__DOT__`
(`/home/docker/Desktop/report__DOT__docx`); decode before matching filenames.

That bucket is private, unlike the public CDS buckets, so artifacts and
trajectories are never downloaded by this bundle.

### Grading

`context.metadata.verifications.<verification_id>`:

- `score` — this run's 0–1 score
- `debug.overall_score`, `debug.metrics[]`
- `results[0].results[0]` → `{id: "agent_judge_multi", score, result, message}`

`message` is free text but reliably structured, and is the only per-criterion
record:

```
agent_judge_multi rubric_only score=0.62 (rubric_score=0.62): <prose>
  Rubric breakdown:
    [must-pass] <title>: score=1.00 weight=10.0 contribution=10.00 PASS (<why>)
    [regular]   <title>: score=0.00 weight=10.0 contribution=0.00 (<why>)
```

```python
BREAKDOWN = re.compile(
    r"\[(must-pass|regular)\]\s+(.*?):\s+score=([\d.]+)\s+weight=([\d.]+)\s+"
    r"contribution=([\d.]+)\s*(PASS|FAIL)?", re.S)
```

The `PASS`/`FAIL` token is often absent — use `score` to decide the outcome.
`sum(contribution)/sum(weight)` reproduces the reported score exactly, so the
parse is self-verifying.

**The judged rubric is often not the shipped one.** Different runs can even
use different versions — watch for more than one `verification_id`.
`bundle.json`'s `agent_runs` block carries `rubric_stale` and `stale_reasons`
when they differ.

## The VM environment

Defined per run, under each agent-run instance's `context.deployed_envs[0]`:
`env_id` (`ubuntu-cua`), `env_version`, `instance_id`, `sandbox_id` /
`sandbox_type`, `gateway_url`, `mcp_url`, `vnc_url`, and
`metadata.cua_vm_sandbox_id` — the **actual desktop VM**, distinct from the env
sandbox. `context.deployed_agents[0]` describes the agent side: `agent_name`,
`a2a_url`, `instance_id`, `sandbox_id`.

All endpoints are `sandbox.internal.scale.com` URLs for sandboxes that expired
within ~8 hours of the run. They are useful as **identifiers and for
correlating runs**, never as live connections — the audit has no VM and no
rendered artifacts.

## Gotchas

- **Select steps by `type`, never by step id** — ids carry random suffixes.
- **`turns` is always empty**; everything is in `before`. The MCP Advanced project is the opposite — don't reuse its paths.
- **Two `ExternalApp` steps.** One is the rubric generator (`data.criteria`), one is the agent run (`data.instances`). Discriminate on which key exists, not on order.
- **`domain` exists only in `task_meta.json`.** The response does not carry it, and without it component 23 scores against the default bands.
- **Domain is not a clean enum** — expect blanks and near-misses (`Software Engineering` vs the canonical `Software & Data`). Normalise before grouping.
- **`golden_*` in the task record means the pre-seeded initial output files, not the answer key.** The answer key is `asset_upload` / `evaluator.expected[]`. The project glossary deprecates "gold file" for this reason; prefer **"expected file"**.
- **`metadata.rubric` uses a dead schema** — `criteria_category` of `"must have criteria"` / `"critical criteria"`, no `criteria_type`. It is the seed, not the contributor's rubric.
- **`prefilled_task` is `false` even when `seed_prompt` is populated.** Check `metadata.seed_prompt` to detect seeded tasks.
- **Exclude non-completed instances** before averaging run scores.
- **`prompt_text` and the judged rubric are run-time snapshots** and may predate the shipped prompt and rubric.
- **Artifact keys encode dots as `__DOT__`.**
- **All sandbox URLs are expired.** Treat them as identifiers.
